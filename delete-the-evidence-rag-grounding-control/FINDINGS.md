# Findings

Run date: 2026-08-20. Hardware: MacBook Pro, Apple M5 Pro, 18 cores, 69 GB.
Model: `KRLabsOrg/lettucedect-base-modernbert-en-v1`, 0.10 s per answer, CPU.
Versions: Python 3.11.10, `lettucedetect` 0.2.3, `scikit-learn` 1.9.0,
`datasets` 5.0.1, `transformers` 5.15.0, `torch` 2.13.0.

Sample: 200 QA rows from the `wandb/RAGTruth-processed` test split, seed 0,
balanced 100 hallucinated / 100 clean.

This file covers the findings the article uses. `results/summary.md`, generated by
`--stage report`, carries the full grid including the third condition and the two
scoring rules the article does not discuss.

## 1. The scoring rule decides what the metric measures

Same model, same 200 answers, same test. Only the rule that collapses per-token
output into one score per answer changes.

| Rule | Own document | Shuffled document | Retained |
| --- | ---: | ---: | ---: |
| `max_token` | 0.912 (CI 0.868-0.947) | 0.581 (CI 0.501-0.657) | **20%** |
| `n_spans` | 0.816 (CI 0.755-0.868) | 0.673 (CI 0.603-0.745) | **55%** |

`max_token` behaves the way a grounding score should: strong with the right
document, near chance without it. `n_spans` keeps more than half its skill after
the document is wrong, so most of what it measures was never about grounding.

`max_token` is also the more accurate of the two in the normal condition, 0.912
against 0.816. There is no trade-off to weigh; it wins on both axes.

## 2. Span count is largely a length proxy

`n_spans` correlates 0.41 with answer length using the real document and 0.42
with the document shuffled. Its relationship to length does not depend on the
document at all, which is why losing the document costs it so little. Answer
length itself correlates 0.37 with the label.

## 3. A word count gets 0.717 for free

Answer length in words, used directly as a hallucination score with no document
at any point: **AUROC 0.717** (CI 0.645-0.784). Hallucinated answers here run a
median 136 words against 97 for clean ones.

That reframes both rules above. `max_token`'s 0.912 is +0.195 over a word count,
not +0.412 over chance, and `n_spans` at 0.816 is barely clear of it.

Part of this is mechanical rather than deep: the label is "contains at least one
unsupported claim", which a longer answer is more likely to satisfy. A length
baseline is worth computing on any corpus with that label shape.

## 4. What the swap does, in plain counts

Given its own document the checker flags 88 of 200 answers. Given a shuffled
document it flags 196 of 200.

It does not start missing hallucinations; it starts accusing almost everything.
Case `13139` is the clean example: an answer explaining how to change computer
sleep settings scores `0.000` against its own document and `1.000` against a
passage about polishing silver jewelry. The checker is not wrong there. Relative
to that passage the answer genuinely is unsupported.

That is why accuracy collapses. Once clean and hallucinated answers both score
near 1.0, the score no longer separates them.

## Scope and limits

- **Reading small gaps.** AUROC gaps below roughly 0.05 to 0.09 sit inside the
  bootstrap interval at this sample size. Treat anything smaller as noise.
- **One corpus, one task type**, and RAGTruth is LettuceDetect's own training
  distribution. The within-checker comparison is valid; these numbers describe
  this corpus, not a reader's traffic.
- **The sample is balanced** 100/100 while real RAGTruth QA runs about 18%
  hallucinated. Review-queue economics at the true base rate are worse than a
  balanced sample suggests.
- **The label treats every hallucination alike**, so 0.912 is an average over
  whatever error mix this corpus contains. It is consistent with catching verbose
  invented prose while missing single-digit numeric errors entirely, which is a
  separate experiment.
- **The transferable result is the test, not the numbers.** Run the swap on your
  own scoring rule and your own labelled set.
